# MatterTable v2 — 筛选与多视图

| 项目 | 内容 |
| --- | --- |
| 版本 | 0.2.0 交付筛选与多视图；0.2.1 修复界面即时性；0.3.0 加日历视图（见 §10）；**0.3.1 修复视图切换后表格只渲染几行（见 §11）** |
| 前置 | v1（MVP）见 `MVP-PRD.md`：表格展示 / 编辑回写 / 列管理 / 排序 / 补骨架 |
| 本版目标 | 把「一张表」变成「多张各自带筛选条件的表」，并支持按日期在月历上查看与调整 |
| 明确不做 | 表格内新建笔记、多选行批量填值（用户明确排除）、**多日任务（start + due 显示成一条跨天条）**（用户明确排除） |

---

## 1. 为什么这两个功能必须一起做

用户最初的规划是「筛选 → 多视图 → 日历」。把前两个放在同一版，原因是它们在数据模型上本来就是一件事：**一个视图 = 一套扫描范围 + 一套筛选条件 + 一套列配置（显隐/顺序/宽度）+ 默认排序**。

- 只做筛选不做多视图：条件改一次看一次，无法沉淀「CS 视图」「本周待办」这种长期入口。
- 只做多视图不做筛选：每个视图只是同一份数据的另一种列布局，价值有限。

所以 v2 交付的是：**视图列表 + 视图切换器 + 每个视图独立的筛选条件**。

## 2. 数据模型

### 2.1 视图配置（`ViewConfig`）

```ts
interface ViewConfig {
  id: string;
  name: string;
  type: 'table';
  scope?: ScopeConfig;        // 视图级扫描范围（新增）
  filter?: ViewFilter;        // 视图级筛选条件（新增）
  sort?: SortSpec[];
  hiddenColumns?: string[];
  columnOrder?: string[];
  columnWidths?: Record<string, number>;
}

interface ViewFilter {
  logic: 'and' | 'or';
  conditions: FilterCondition[];
}

interface FilterCondition {
  id: string;                 // 界面上增删条件用的稳定 id
  key: string;                // 字段 key，也可以是文件名列 __file
  operator: FilterOperator;   // equals / notEquals / contains / notContains / gt / lt / isEmpty / isNotEmpty
  value?: string | number | boolean | null;
}
```

配置里额外增加 `activeViewId`（当前激活的视图，跟库走，换机器也记得）。

### 2.2 配置文件示例

```jsonc
{
  "scope": { "root": "", "include": ["**/*.md"], "exclude": ["**/node_modules/**", "**/20 Raw/**", "5 Projects/**"] },
  "views": [
    {
      "id": "default",
      "name": "全部笔记",
      "type": "table",
      "filter": { "logic": "and", "conditions": [] },
      "sort": [],
      "hiddenColumns": ["description"]
    },
    {
      "id": "view-cs",
      "name": "CS 笔记",
      "type": "table",
      "scope": { "exclude": ["**/22 Leetcode/**"] },      // 与全局 exclude 取并集
      "filter": {
        "logic": "and",
        "conditions": [
          { "id": "c1", "key": "categories", "operator": "equals", "value": "CS" },
          { "id": "c2", "key": "state", "operator": "notEquals", "value": "finished" }
        ]
      }
    },
    {
      "id": "view-agent",
      "name": "Agent 开发",
      "type": "table",
      "scope": { "root": "D:/KnowledgeBase/3 Agent Dev" },  // 只扫这个目录
      "filter": { "logic": "and", "conditions": [{ "id": "c1", "key": "tags", "operator": "contains", "value": "Agent" }] }
    }
  ],
  "activeViewId": "default"
}
```

### 2.3 视图级扫描范围的语义

| 字段 | 语义 |
| --- | --- |
| `scope.root` | 不填 = 用全局 `scope.root`（默认就是工作区根目录）；填了就用它 |
| `scope.include` | 不填 = 用全局的（默认 `**/*.md`） |
| `scope.exclude` | **与全局取并集**：视图只能「多忽略一些」，不能取消全局忽略。理由：全局忽略清单是数据安全边界（排除依赖目录、第三方仓库），不该被某个视图绕过 |

**什么时候需要重新扫描？** 只有扫描范围（root/include/exclude 合并后的结果）真的变了才重新走目录。同一范围内的视图之间切换是**瞬时的**（行数据已经在内存里）。改筛选条件**永远不重新扫描**——筛选完全在前端做。

## 3. 筛选语义

### 3.1 每个字段类型可用的操作符

| 字段类型 | 可用操作符 | 值的输入方式 |
| --- | --- | --- |
| 文本 | 等于、不等于、包含、不包含、为空、不为空 | 文本输入框 |
| 数字 | 等于、不等于、大于、小于、为空、不为空 | 数字输入框 |
| 日期 | 等于、不等于、晚于、早于、为空、不为空 | 日期选择器 |
| 单选 | 等于、不等于、为空、不为空 | 选项下拉 |
| 多选 | 包含任一、不包含任何、为空、不为空 | 选项下拉（单值） |
| 复选框 | 等于（已勾选/未勾选）、未设置 | 已勾选/未勾选下拉 |
| 文件名列 | 同文本 | 文本输入框 |

### 3.2 比较规则（实现细节，避免「明明有却筛不出来」）

| 规则 | 说明 |
| --- | --- |
| 文本相等 | 忽略大小写与全半角差异（与「包含」的宽松程度一致） |
| 文本包含 | 子串匹配，忽略大小写 |
| 数字比较 | 转成数字再比；解析不出数字的值不参与匹配 |
| 日期比较 | 按 `YYYY-MM-DD` 字符串比较（ISO 格式下字典序 = 时间序），所以「早于 / 晚于」是正确的 |
| 多选包含 | 任何一个值命中即算命中（`面` 能匹配 `面试`） |
| 「为空」的定义 | 文本/数字/日期：值为 null 或空串；单选/多选：值列表里没有任何有效项（`categories:` + `- ` 这种空项也算空）；复选框：值为 null（未设置） |
| 多条件关系 | `and` = 全部满足，`or` = 任一满足（一层组合，不做嵌套分组） |

### 3.3 容错规则（不打断用户）

| 情况 | 行为 |
| --- | --- |
| 条件引用的字段不存在（字段被改名/删除） | **不筛掉任何行**，条件上标注「字段已不存在」，不报错 |
| 条件还没填值（例如刚添加、值是空的） | 视为该条件不生效，不筛掉任何行 |
| 字段类型变了导致操作符不适用 | 配置加载时按字段类型回落到该类型的第一个合法操作符 |
| 选中的选项后来从选项池里消失 | 下拉里显示为「xxx（未定义）」并保留，不会静默改成别的值 |

## 4. 界面

### 4.1 视图切换器（工具栏最左）

按钮显示当前视图名（`视图：全部笔记 ▾`），点开是一个面板：

- **视图列表**：当前视图前面是 ●，每项右侧显示「N 个条件」「路径 xxx」等摘要；点击即切换
- **＋ 新建视图**（不含筛选条件，会继承当前的列设置）
- **⧉ 复制当前视图**（含筛选条件与列设置）
- **✎ 重命名当前视图**（内联输入框，回车确认）
- **⌂ 当前视图的扫描范围…**（填根目录 + 额外忽略，一行一条 glob）
- **✕ 删除当前视图**（只剩一个视图时禁用，并提示）

### 4.2 筛选条件栏（工具栏下方一条）

```
筛选  [状态 ▾equals] [finished ▾] ×   [标签 ▾包含任一] [Agent ▾] ×   全部满足▾   ＋ 添加条件   清除
```

- 每个条件是一颗「药丸」：字段名 + 操作符下拉 + 值编辑器 + 移除按钮；hover 显示人话描述（如「日期 早于 2026-01-01」）
- 两个及以上条件时出现 `全部满足 / 任一满足` 切换
- `＋ 添加条件` 弹出字段列表（嵌套结构字段不可筛选）
- 有筛选时，右上角统计从「N 个文件」变成「显示 X / 共 Y 行」

### 4.3 筛选不影响写入

筛选只是显示层的过滤：在筛选后的表格里编辑单元格，写回逻辑与 v1 完全一致（改的还是那个文件的 front matter）。这一点有专门的验收项（见下）。

## 5. 消息协议新增

宿主 → 界面：

| 消息 | 用途 |
| --- | --- |
| `init`（扩展） | 现在同时带上 `views`（全部视图）与 `view`（当前视图） |
| `viewsUpdated` | 视图列表或筛选条件变了（新建/复制/重命名/删除/切换）。**不带行数据**，避免打断正在输入的条件 |

界面 → 宿主：

| 消息 | 用途 |
| --- | --- |
| `switchView` | 切换视图（同范围不重扫） |
| `createView` / `duplicateView` / `renameView` / `deleteView` | 视图增删改 |
| `setViewFilter` | 保存某视图的筛选条件（防抖落盘，不回传数据） |
| `setViewScope` | 保存某视图的扫描范围（会重新扫描） |

## 6. 性能设计

| 动作 | 是否重新扫描目录 | 预期耗时 |
| --- | --- | --- |
| 改筛选条件 | 否（纯前端过滤） | 瞬时 |
| 在筛选栏里打字 | 否 | 瞬时 |
| 切换视图（扫描范围相同） | 否（行数据在内存里） | 瞬时 |
| 切换视图（扫描范围不同） | 是（有行缓存，多数文件只做 stat） | 百毫秒级 |
| 视图里改单元格 | 否（只重解析那一行） | 瞬时 |

**实现要点：行缓存不再按当前扫描结果做 prune。** 因为不同视图可能只扫同一个根目录的子集，按当前结果清理缓存会把别的视图已缓存的解析结果删掉；删除文件由文件监听负责清理。

## 7. 验收标准

1. **视图隔离**：两个视图各自的筛选条件、列显隐、列顺序、排序互不影响；重开表格后仍是各自的样子。
2. **筛选正确性**：六种字段类型 × 各自操作符的结果符合第 3 节的语义表（由 20 个筛选引擎单测覆盖）。
3. **组合逻辑**：两个条件时 AND / OR 切换结果正确。
4. **容错**：条件引用不存在的字段时，表格不筛掉任何行且给出提示，不弹错误。
5. **视图级范围**：给视图设 `root` 或 `exclude` 后行数随之变化；全局忽略清单依然生效（并集）。
6. **切视图性能**：同一扫描范围的两个视图来回切换时不出现「正在扫描」提示，滚动位置重置但行数据不重新读盘。
7. **筛选后仍可写回**：在筛选结果里改一个单元格，文件里对应字段被正确改写、其他字节不变。
8. **持久化**：视图的新建/重命名/删除/筛选条件/扫描范围都写进 `.mattertable/config.json`，手改配置也能生效。

## 8. 已知取舍与后续

| 取舍 | 原因 | 后续 |
| --- | --- | --- |
| 筛选只有一层 AND/OR，不做嵌套分组 | 嵌套分组需要树形条件编辑器，成本高、日常用不到 | 需要时在 v3 做 |
| 多选的「包含」是单值 | 「包含任一 A 或 B」可以用两个条件 + OR 表达 | v3 可做成多值选择 |
| 不能按「相对时间」筛选（如「最近 7 天」） | 需要动态求值，且要考虑「今天」的刷新时机 | v3 候选 |
| 筛选条件不能跨视图复用（只能整视图复制） | 够用；复制视图即可 | 需要时做「保存的筛选片段」 |
| 日历视图 | 依赖视图模型先落地；本版已把它需要的基础设施（视图级配置、日期字段可用）准备好了 | v2.1 |

## 9. 修复记录（0.2.1，第一次人工测试发现）

第一次人工测试报了 3 个问题，其中第 1、2 个是同一个根因，值得记下来：

| 现象 | 根因 | 修法 |
| --- | --- | --- |
| 点「添加条件」后看不见操作符选项、点「清除」不生效，**都必须刷新** | 界面把筛选条件**只发给了宿主机**去持久化，而宿主机对 `setViewFilter` 是「只持久化、不回传数据」的（当时是为了不打断用户输入）。其他视图属性（列显隐/排序/列宽）界面都会自己先更新，唯独筛选漏了这一步——于是界面一直显示旧状态，直到下一次刷新（宿主机重发全量数据）才对上 | 筛选条件改成**界面先本地更新、再发给宿主机持久化**，与其他视图属性一致 |
| 操作符下拉里「等于/不等于/包含…」白底白字，不 hover 看不见 | 原生 `<select>` 展开后的选项列表由浏览器/系统绘制，不受自定义 CSS 中的容器样式影响；深色主题下系统用浅色背景，而文字色继承了我的深色主题前景色 | `body` 上按编辑器主题声明 `color-scheme`；另外显式给 `option` 指定下拉背景/前景色（双保险） |
| 消息提示挤在顶部、遮挡布局、要手动关闭 | 提示条是 flex 布局里的一块，出现时会把表格往下推 | 改为**右下角浮层 toast**：绝对定位不占布局、提示类自动淡出、错误类保留、内容相同的去重 |

**测试策略上的教训（第二次同类问题）**：这次漏掉的原因是——组件测试只断言了「发出正确的消息」，没有断言「界面出现了用户能看到的变化」。于是「只发消息、不更新界面」这种 bug 完全测不出来。修完之后补的 4 个回归用例，全部改成**断言语义结果**（条件药丸数量、行数变化、统计里的 X / 共 Y），而不是断言消息内容。

> 这条教训第一次出现在 v0.1.1（当时只测了宿主逻辑、没渲染 DOM）。两次都指向同一条原则：**测试要断言用户能观察到的结果，而不是断言实现动作。**

## 10. 日历视图（v2.1 / 0.3.0）

### 10.1 需求（用户原话）

> 「date 不为空（不硬编码 date）的笔记渲染在月视图上，点击跳转，拖拽改日期，同样支持筛选。明确不做多日任务（比如 startdate、duedate 两个字段想显示成一条）——这太复杂了。」

### 10.2 数据模型

```ts
interface ViewConfig {
  type: 'table' | 'calendar';   // 视图类型（新增 calendar）
  dateField?: string;           // 日历用哪个字段归类；不填 = 自动取第一个 date 类型字段
  // 其余（scope / filter / sort / hiddenColumns / columnWidths）表格与日历共用
}
```

**「不硬编码 date」怎么落实的：**

| 情况 | 行为 |
| --- | --- |
| 视图配置里写了 `dateField` | 用它 |
| 配置里没写 | 自动取**第一个 `type: "date"` 的字段**（不是找名叫 `date` 的字段） |
| 配置里的 `dateField` 已被删除/改名 | 回退到第一个 `date` 类型字段，并保持配置不变（不静默改写用户的选择） |
| 整个扫描范围里没有任何 `date` 类型字段 | 显示空状态，并告诉用户「在配置里给某个字段声明 `"type": "date"`」 |

日历上方还有一个「日期字段」下拉，列出所有 `date` 类型字段，可以随时切换（写回配置，跟库走）。

### 10.3 日期值怎么解析

- 只认 `YYYY-MM-DD`；写成 `2026-9-6` 这种不规范格式不会被认出来（写入时也是按 `YYYY-MM-DD` 规范化的，所以正常编辑过的值一定合规）
- 兼容带时间的字符串：`2026-01-28T03:08:15.761075` 会取日期部分 `2026-01-28`（这样 `created_at` 这类字段也能当日历字段用）
- 列表值取第一个有效日期
- 无效值（`待定`、数字、布尔）与空值一律视为「没有日期」
- 一律按**本地日期**处理，避免时区把日期挪一天

### 10.4 界面与交互

| 元素 | 行为 |
| --- | --- |
| 月份导航 | `‹` 上个月、`›` 下个月、「今天」回到本月；标题显示 `2026 年 9 月` |
| 月网格 | 周一起始、固定 6 行 × 7 列（固定行数是为了翻月时高度不跳）；不属于本月的日子灰显；今天有高亮边框 |
| 卡片 | 显示 `title` 字段的值，没有 title 就显示文件名（去掉 `.md`）；hover 显示相对路径 |
| 点击卡片 | 在新标签页打开该文件 |
| 拖拽卡片到另一天 | **直接改日期并写回文件**；拖动时目标格高亮，松手高亮消失；卡片立刻移动到新日期（界面先本地生效再写盘） |
| 未排期的笔记 | 不进网格，但顶部统计显示「另有 N 项没有日期」，不会悄悄消失 |
| 筛选 | 完全复用 v2 的筛选条件栏；被筛掉的不出现在日历里。若筛选结果里一条有日期的都没有，显示一条说明而不是一片空白 |
| 工具栏 | 日历视图下自动隐藏表格专属项（「字段」列管理、显示无 front matter 的开关、表格行数统计） |

### 10.5 写回通道与表格完全一致

拖拽改日期发的就是表格编辑用的那条 `setCell` 消息，所以自动继承全部数据安全机制：

- 行级最小改写（只替换日期那一段字节，CRLF/BOM/引号/注释不动）
- 写入前校验「文件是否被外部改过」（时间 + 大小）
- 文件在编辑器里未保存时拒绝写入
- front matter 非法 / 嵌套结构字段拒绝写入
- `MatterTable: 撤销上一次改动` 同样能撤销拖拽造成的改动

## 11. 修复记录（0.3.1，用户在真库上发现）

**症状**：如果面板是在日历视图下打开的，之后切到表格视图，表格只渲染最上面约 8 行、下面全是空白；退出重开（一进来就是表格）则正常。

**根因是两件事叠加**：

1. 视口高度的 `ResizeObserver` 只在组件挂载时建立一次（effect 依赖写成了 `[]`）。在日历视图下挂载时 `.grid` 元素还不存在（表格是条件渲染），观察器根本没建立；之后切回表格也不会补上，于是视口高度一直停留在初始值。
2. 从表格切到日历时，旧的 `.grid` 元素被卸载，浏览器会向观察器报告 **0 高度**，而代码把这个 0 直接写进了状态 → 视口高度变 0 → 虚拟滚动只渲染 overscan 的 8 行（与你截图里恰好 8 行吻合）。

**修法三处**：effect 依赖改为视图类型（切换后重新挂到新的 DOM 元素上）、**忽略非正数高度**（面板切到后台时高度也是 0）、以及在视口高度未知时用 600px 兜底——宁可多渲染几行，也不能退化成几行。

**回归测试**：新增 2 项，用「触发一次 0 高度测量」模拟面板切到后台或元素被卸载。把修复回退后这两项会失败，失败信息正是 `expected 8 to be greater than 20`，说明它们确实盯住了这个 bug，而不是碰巧通过。
